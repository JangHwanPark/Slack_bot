## 지금까지 한 것

**슬랙 봇 골격.** Socket Mode로 동작한다. 공인 IP, 도메인, 인증서가 필요 없고
아웃바운드 HTTPS만 열려 있으면 사내망 안에서도 돈다.

**Gmail 연동 완료.** 개인 OAuth refresh token 방식으로 붙였고 실제 메일함으로 검증했다.
테스트 메일 3통을 보내 픽스처와 동일한 추출 결과를 확인했다.
Gmail이 마크다운 본문을 HTML로 바꿔 보내도 파싱이 된다.

**추출 계층.** 메일 본문에서 빌드 정보 8종(버전, 빌드, 플랫폼, 환경, 브랜치, 커밋,
다운로드, 빌드 페이지)과 지라 이슈 참조를 뽑는다. 규칙은 `src/extract/rules.js` 한 곳에 모았다.

**커맨드 두 개.** 채널 자동 게시가 아니라 커맨드를 칠 때만 조회하는 방식이다.
응답은 명령을 친 사람에게만 보인다.

| 커맨드 | 동작 |
| --- | --- |
| `/server` \| `/server all` | 세 서버의 최근 테스트 요청 정보 |
| `/server beta` \| `beta2` \| `hotfix` | 해당 서버 하나 |
| `/qa list` | 최근 테스트 요청 목록 (번호 붙음) |
| `/qa show <번호>` | 목록에서 고른 요청 상세 |
| `/qa latest` | 가장 최근 1건 상세 |
| `/qa refresh` | 메일 다시 읽고 목록 |
| `/qa help` | 도움말 |

## 지금 설정 상태

로컬 `.env` 기준이다. 저장소에는 없다.

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 슬랙 토큰 | 설정됨 | |
| `SLACK_NOTIFY_CHANNEL` | 비어 있음 | 채널 게시를 켤 때만 필요 |
| `MAIL_SOURCE` | `gmail` | `fixture`로 바꾸면 로컬 파일을 읽는다 |
| `MAIL_QUERY` | `subject:(테스트 요청) newer_than:1d` | 자기가 보낸 메일은 읽음 처리되어 `is:unread`로는 안 잡힌다 |
| 구글 OAuth | 설정됨 | refresh token 발급 완료 |
| `JIRA_TYPE` | `none` | 주소와 토큰이 없어 조회를 건너뛴다 |
| `SERVER_*_URL` | 비어 있음 | 헬스 체크 끔 |
| `POLL_ENABLED` | `false` | 채널 자동 게시 끔 |

## 잠들어 있는 기능

지운 게 아니라 설정으로 꺼둔 것들이다. 값만 채우면 그대로 살아난다.

**지라 조회.** `JIRA_TYPE`을 `cloud` 또는 `server`로 바꾸고 주소와 토큰을 넣으면
이슈 제목, 상태, 우선순위, 담당자가 카드에 붙는다. Cloud는 REST v3에 이메일+토큰 베이직 인증,
Server는 REST v2에 PAT 베어러 인증으로 자동 분기한다. 지금은 본문에서 찾은 링크와 키만 표시된다.

**서버 헬스 체크.** `SERVER_<이름>_URL`을 채우면 실제 HTTP 요청을 보내
상태 코드, 응답 시간, 응답 JSON의 버전과 커밋을 보여준다.
이때 "서버 응답"과 "테스트 요청 메일" 두 섹션이 함께 뜨고,
실행 중인 버전과 메일이 요청한 버전이 다르면 경고 줄이 붙는다.
구버전을 테스트하는 사고를 막는 용도다.
다만 외주 개발사가 헬스 엔드포인트를 열어줄 가능성이 낮아 당분간 쓸 일이 없을 것이다.

**채널 자동 게시.** `POLL_ENABLED=true`와 `SLACK_NOTIFY_CHANNEL`을 채우면
주기적으로 메일을 확인해 새 요청을 채널에 올린다. 이미 알린 메일은 `data/seen-mails.json`으로 걸러낸다.

## 다음에 할 일

**회사 적용이 남은 전부다.** 순서대로 하면 된다.

1. 실제 테스트 요청 메일을 `fixtures/mails/*.txt`로 저장한다
   (첫 줄 `Subject:`, `From:`, 빈 줄, 그 뒤 본문)
2. `node scripts/extract-preview.js <파일>` 로 무엇이 잡히고 무엇이 빠지는지 본다
3. `src/extract/rules.js`의 라벨 목록을 회사 양식에 맞게 고친다. 다른 파일은 건드릴 필요가 없다
4. `node scripts/gmail-dry-run.js` 로 실제 메일함에서 확인한다
5. `MAIL_QUERY`를 실제 요청 메일만 걸러내는 검색식으로 맞춘다
6. 지라 주소와 토큰을 받으면 `JIRA_TYPE`을 바꾼다

**Slack 앱 설정.** 워크스페이스가 바뀌면 `/server`와 `/qa`를 다시 등록하고 재설치해야 한다.
Socket Mode라 Request URL은 필요 없다. 봇 스코프는 `chat:write`, `commands`.

**배포.** 상시로 쓰려면 계속 켜져 있는 곳에 올려야 한다.
`npm ci` 후 `pm2 start index.js --name slack-qa-bot`.
지라나 빌드 서버가 사내망에만 있으면 봇도 사내망 안에 두어야 한다.

## 알아둘 것

**서버 이름과 메일을 짝짓는 방법.** `/server beta`는 메일에서 뽑은 `환경` 값이
`beta`인 요청을 먼저 찾고, 없으면 제목이나 본문에 `beta`가 들어간 메일을 찾는다.
회사 메일에 환경 표기가 없으면 이 매칭이 헐거워질 수 있다.

**조회 결과는 30초간 재사용한다.** `/qa list` 직후 `/qa show 2`를 쳐도 번호가 어긋나지 않는다.
최신 상태가 필요하면 `/qa refresh`.

**메일 양식이 다르면 어떻게 되는지.** `fixtures/mails/sample-other-format.txt`가 그 예다.
`앱 버전 : 3.0.1 (빌드 512)` 처럼 빌드 번호가 괄호 안에 있으면 버전 값이 통째로 잡힌다.
8개 중 4개만 추출된다. 회사 양식이 이런 식이면 `rules.js`에 전용 패턴을 추가해야 한다.

**테스트용 메일 원고**는 `docs/test-mails.md`에 있다. 복붙해서 보내면 된다.
